# Documentation

One markdown file per feature/epic, created or updated when that feature reaches a meaningful milestone. Each file should cover:

- What the feature does, product-level.
- Key files and their responsibilities.
- Architecture/state-management notes specific to the feature.
- Reused components vs. new ones (and why, if new).
- Known gaps (including that tests are deferred — see `TASKS.md` Epic 16).

See `PROJECT_CONTEXT.md` at the project root for the always-current whole-app snapshot, and `.claude/skills/nutrition-app-workflow` for the process this follows.
