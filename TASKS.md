## Epic 15 — Security Hardening — IN PROGRESS (started 2026-09-21)
- [x] Firestore & Storage rules review (Instrucciones.md §80). **Real vulnerability found and fixed**: `firestore.rules`' original `users/{userId}` rule (`allow read, write: if request.auth.uid == userId`, no field restriction) let a client write ANY field on their own user document — including `subscription.isPremium`, which several Cloud Functions read as the server-trusted premium flag (Instrucciones.md §70 "DO NOT TRUST CLIENT-SIDE PREMIUM STATUS").
